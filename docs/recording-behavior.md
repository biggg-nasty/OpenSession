# Recording behaviour: references, OpenSession implementation, verification

This document links observable recording behaviour in four reference DAWs to what OpenSession does and how each behaviour is verified.

**How the reference column was produced.** Official vendor documentation was read on **2026-10-31** (URLs and page versions in the Sources section). None of the four applications was run by us; nothing below is a direct observation of Logic Pro, Pro Tools, Live or REAPER. Evidence status per reference entry:

| Status | Meaning |
|---|---|
| DOCUMENTED | Stated on the cited official page |
| INFERRED | Reasonable inference from the cited documentation, not stated explicitly |
| UNKNOWN | Not found, or the page could not be loaded |
| RECOLLECTION (unverified) | From memory only; the page that would confirm it failed to load |
| PRODUCT-CHOSEN (ours) | An OpenSession decision, not a copy of any reference |

Reference versions: Logic Pro for Mac 12.3 user guide; Ableton Reference Manual Version 12; Pro Tools Reference Guide 2026.4 (PDF); "Up and Running: A REAPER User Guide v7.84" (PDF from reaper.fm).

**Verification column.** Test titles are the exact `TEST_CASE` names in `Source/Tests/*.cpp`, run headlessly with `OpenSession --run-tests` against the engine's hosted audio device (synthetic input, no hardware). Current result: 38 test cases, 581 assertions, all passing (Debug build, session 3). Hardware status is one of:

- `hardware: verified on MacBook Pro built-in mic, macOS 27.0.1` (CoreAudio, 48 kHz, 512-frame buffer, 1 input channel)
- `hardware: not yet verified (no external interface attached)`

OpenSession build described here: 0.1.0 on Tracktion Engine develop `a5e44996` (3.5.0) and JUCE 9.0.5.

## Common behaviours we adopted as defaults

1. Per-track arming before recording; Transport Rec writes every armed track at once (all four DAWs).
2. Mono vs stereo decided by the chosen input; a mono input records a mono file (Live, REAPER).
3. Non-destructive recording: a new pass never erases earlier audio (all four).
4. After an overdub only the newest take plays; alternates are auditioned by selecting them (Live and Pro Tools verbatim; Logic and REAPER inferred).
5. Edits never modify source files; multi-step undo (all four).
6. Click generated on a separate internal path and never part of an audio recording (all four).
7. Latency compensation automatic from driver-reported figures, manual offset reserved for a measured residual (Logic, REAPER, Live).
8. A collect/consolidate command that copies referenced audio into the project folder (all four).
9. Stems are one post-fader file per track over a common range (all four).

## Where we deliberately differ

| Topic | Reference spread | OpenSession choice | Why |
|---|---|---|---|
| Default monitoring | Live Off (audio), Pro Tools Auto Input, REAPER Monitor Input on, Logic global + per-track | **OFF** on every input until the user sets AUTO or ON | A first-time user with interface direct monitoring would otherwise hear a latency double; the setup screen explains both options |
| Monitoring during punch | Tape-style auto-input in all four | Not implemented (AUTO = armed) | Punch recording deferred; whole-take overdubs do not need it |
| Arm exclusivity | Live exclusive unless modifier; others latch | Latch | Multi-input tracking is the primary scenario |
| Take alternatives UI | Folder (Logic), hidden playlists (Pro Tools), lanes (Live, REAPER lanes mode) | Lanes under the track; muted takes stay visible | Keeps the "what is on disk" picture honest and the audition a single click |
| Overlap rule | REAPER "Play all takes" opt-in; Live one lane audible | Exactly one active clip per overlap group; activating mutes whole overlapping clips | Simple and predictable; range comping comes later |
| Record with effects | REAPER only | Not offered | Dry capture guarantee is tested and documented |
| Keep monitoring latency in recording | Live option (default on) | Not offered; recordings sit where the sound entered the input | One timing model is easier to reason about and to test |
| Count-in | None stated as default by any vendor | One bar (toggle), click on, for new sessions | Product decision for the guitar + vocal demo |
| Export tail | Logic checkbox, REAPER value, others none | Per-session choice (none / 2 / 5 / 10 s, default 2 s), applied equally to mix and stems | Guarantees mix and stems share range and length whatever the tail |
| Project container | Package/folder/plain file variants | Folder with relative paths, atomic saves, snapshot + autosave | Portability and recovery were required from the first milestone |

# Reference DAW recording behaviour (draft)

Research notes for OpenSession. All claims below come from official vendor documentation that was actually loaded on **2026-10-31**. Nothing here was observed by running the applications. Evidence status per entry is one of **DOCUMENTED** (read on the cited official page), **INFERRED** (reasonable inference from the cited documentation, not stated explicitly), or **UNKNOWN** (not found / fetch failed). Anything drawn from memory is marked **RECOLLECTION (unverified)**.

Conventions:
- Logic Pro pages were loaded from the unversioned `/mac` URLs; the page's version selector and table-of-contents links identify the guide as **Logic Pro for Mac 12.3** (article bodies do not restate the version).
- Ableton pages were loaded from `https://www.ableton.com/en/live-manual/12/...`; the page header reads "Ableton Reference Manual Version 12" (patch level not stated).
- Pro Tools quotes come from the **Pro Tools Reference Guide version 2026.4** PDF ("Created 4/7/2026 • REV A"). Page numbers are the guide's printed page numbers.

## Common across all four (candidate defaults for OpenSession)

1. **Per-track record arm** is required before recording; transport Record then writes to every armed track at once; simultaneous track count is limited only by enabled hardware inputs (DOCUMENTED for all four).
2. **Mono vs stereo is decided per track by the chosen input** (Live, REAPER: input choice decides file channel count; Logic/Pro Tools: track/channel-strip format plus matching input). A mono input should record a mono file.
3. **Default recording is non-destructive**: recording over existing material keeps the old audio (Logic take folders, Pro Tools Normal mode / alternate takes, Live take lanes, REAPER "split existing items and add takes"); destructive modes exist only as explicit options (Logic Replace, Pro Tools Destructive Record, REAPER tape mode).
4. **Only one take/lane is audible per track by default** after an overdub; the newest recording is the one that plays (Live and Pro Tools state this verbatim; Logic/REAPER inferred). Alternates are auditioned by selecting them, and simultaneous playback is an opt-in (REAPER "Play all takes", REAPER "Add lanes (all lanes play)", Logic MIDI "Overlap").
5. **Edits (split/trim/move/fade/gain) never modify the source audio file**; all four keep an edit list over immutable files and provide a multi-step Undo History window.
6. **Software (DAW-side) input monitoring is the default**, with an option to turn it off for hardware/direct monitoring, and all four implement a "tape-style" auto-input behaviour for punching (Logic Auto Input Monitoring, Pro Tools Auto Input, Live Auto, REAPER tape auto style).
7. **Metronome click is generated on a separate internal channel and is not written into audio-track recordings**; every DAW offers "click only while recording / only during count-in" style conditions and a count-in measured in bars.
8. **Recording-latency compensation is automatic from driver-reported latency**, with a manual fixed offset reserved for correcting driver misreports (Logic Recording Delay, REAPER manual offsets, Live's Overall Latency / driver-error adjustment; Pro Tools exposes manual values only for HD hardware/inserts).
9. **A "save with media / collect" command** copies referenced audio into the project folder for portability (Consolidate, Save Copy In, Collect All and Save, Copy all media into project directory).
10. **Stem export is one post-fader file per track over a common range**, with options for format/bit depth and whether to print effects (Logic Bypass Effect Plug-ins, REAPER Consolidate vs Render; Live/Pro Tools always post-FX).

## Behaviours that differ (candidate product decisions)

1. **Default monitor mode for audio tracks**: Live documents the reset default as "Off" for audio tracks (Auto for MIDI) while also saying armed tracks are auto-monitored; Logic requires the global Software Monitoring plus auto-input; Pro Tools defaults to Auto Input on every track; REAPER defaults to Monitor Input always-on. Decision: pick Auto (tape-style) vs always-on vs off by default.
2. **Where take alternatives live**: Logic nests them in a take folder on the same track; Pro Tools hides them as matching clips/playlists; Live and REAPER (lanes mode) show parallel lanes under the track. Decision: lanes vs folder UI.
3. **What happens on a non-looped overdub**: Logic (Cycle Off) creates a take folder; Pro Tools leaves the new clip on top and the old one in the Clip List; Live adds a take lane and copies the new clip to the main lane; REAPER splits and adds a take. All agree the new recording is what plays.
4. **Loop recording output**: Logic creates a take folder from pass 2; Pro Tools writes one file with numbered clips; Live writes one long sample and exposes passes via the loop brace; REAPER adds media on stop (preference). Decision: one file per pass vs one long file.
5. **Record-with-effects option**: only REAPER offers a per-track "Record: output (post-FX)" switch; the others require resampling/bussing or exporting afterwards. Decision: offer a REAPER-style input/output record source or stay dry-only.
6. **Recording-offset UI**: Logic exposes a single Recording Delay slider; REAPER exposes automatic plus manual values; Live references a driver-error adjustment and a per-track "Keep Monitoring Latency in Recorded Audio" toggle; Pro Tools has no manual offset on native systems. Decision: expose a global manual offset in samples/ms and whether to shift recordings by monitoring latency.
7. **Count-in defaults and limits**: Logic offers None, 1-6 bars or beat fractions plus a seconds pre-roll; Live and Pro Tools let the user set bars; REAPER separates count-in from a 2-measure pre-roll. No DAW's default length was stated on the pages read.
8. **Track arming exclusivity**: Live un-arms other tracks unless a modifier is held; Pro Tools latches by default with "cancel previous" options; Logic and REAPER latch. Decision: latch vs exclusive arm by default.
9. **Tail handling on export**: Logic has an explicit "Include Audio Tail" checkbox; REAPER has a tail-length value and 2nd-pass render; Live and Pro Tools rely on the render range/selection. Decision: add an explicit tail option.
10. **Project container**: Logic package or folder with per-asset copy/reference; Live project folder with Samples/Recorded; REAPER plain .RPP with optional relative paths; Pro Tools session folder with Save Copy In. Decision: folder-based project with relative paths by default plus a Collect/Consolidate command.

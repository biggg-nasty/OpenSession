All prices and figures were read on **2026-10-31** from the URLs given. "Primary" means the vendor's own page or an official filing; "secondary" means a news or retailer page because the official page would not load (HTTP 403/404) or did not render the figure. Prices are consumer list prices excluding tax where the vendor says so. Raw notes with verbatim quotations are in `docs/research/cost-and-competition-draft.md`.

## 5. Where OpenSession differs

These are things the current build actually does; each is covered by the self-test suite described in `docs/test-results.md` unless marked otherwise.

| Behaviour | What the build does | Evidence |
|---|---|---|
| Explicit input setup | Every hardware channel appears as a named input; a track has no input until you choose one; arming without an input is refused with a message; a live input meter reads the real device level; monitoring state (OFF / AUTO / ON) is shown per input and is independent of arming | Tests "Recording: arming needs an input ..." and "Recording: monitoring mode is explicit and independent of arming"; input level printed by `--smoke-record` on the built-in mic |
| Dry capture guarantee | Recordings tap the device input only; fader, pan, inserts, click and playback of other tracks never enter the file | Tests "Recording: fader, pan and insert effects do not alter the dry recording" and "Recording: existing-track playback, click and software monitoring never reach the dry recording" |
| Takes with one-click audition | Each pass is kept as its own file; overlapping clips form a take group with exactly one active; double-click or Cmd+K swaps the active take | Tests "Recording: repeated passes over the same range become takes ..." and "Editing: take groups ..." |
| Portable, recoverable sessions | Folder session with relative paths; atomic saves with a previous snapshot; autosave; collect-and-save; aborted takes preserved under `Audio/Incomplete`; unfinalised WAV headers repaired; orphan recordings recovered at their BWAV time stamp | Twelve "Session: ..." tests plus "Recording: aborting a take mid-way ..." |
| Aligned stems | Mix and stems rendered over one range (0 to last clip end + 2 s); stems share start and length; nothing normalised; clipping reported | Tests "Mix/export: stems share one timeline start and length ..." and "Mix/export: clipping is measured and reported ..." |
| Proven, not promised | `OpenSession --run-tests` runs 33 deterministic cases (516 assertions) against a hosted audio device with synthetic signals | `docs/test-results.md` |
| Honest latency reporting | Buffer duration, driver-reported latency and measured residual are shown as three separate numbers; the loopback calibrator applies only the residual | Audio Settings panel; loopback measurement not yet run on hardware |

What OpenSession does not have yet (and the alternatives do): plug-in hosting, MIDI and virtual instruments, automation, punch recording, range comping, loop recording, video, surround. See `docs/architecture.md` for the extension points.

## 6. Hypotheses to test with musicians

No musician sessions have been run yet. The protocol below is the plan, not a result.

| Hypothesis (from the brief) | Measure | Procedure |
|---|---|---|
| Clearer input setup | Time from launch to "input meter moving on an armed track"; number of wrong-input or no-input errors | Fresh install, interface connected; participant told only "record your guitar" |
| Faster take workflow | Time to record two passes and select the better one; number of accidental double takes heard | Record guitar twice over the same bars, audition, pick one |
| Straightforward portability | Session reopened on a second machine with all audio present (yes/no); time to find the files | Copy the `.osession` folder by USB stick to another Mac, reopen |
| Predictable cost | Participant's expected cost vs actual (0) | Exit question |
| Overall | Completion of the full demo flow (select interface, arm, record to click, overdub, audition, edit, mix, save/reopen, export and play the WAV); errors encountered; free-text feedback | Observed session, notes per step |

Record for every session: OS version, interface model, sample rate, buffer size, number of tracks, duration, any dropouts, and whether the participant used direct or software monitoring.

| JUCE | `7ff644f65d7daa1428c34b9738ebb5c449dc9172` (9.0.5, the engine's submodule) | AGPLv3 option of its dual AGPLv3/commercial licence | `third_party/tracktion_engine/modules/juce/LICENSE.md` (states "dual-licensed under the AGPLv3 and the commercial JUCE licence"); https://juce.com/get-juce/ |
| Bundled third-party code inside the engine | choc (ISC), crill (BSL-1.0), doctest (MIT), expected (CC0 1.0), libsamplerate (BSD-2-Clause), magic_enum (MIT), rigtorp (MIT), rpmalloc (public domain); plus JUCE's own bundled libraries | Permissive; listed in `THIRD_PARTY_NOTICES.md` | engine README and `modules/3rd_party` listing |

How the pieces combine: GPLv3 section 13 permits combining a GPLv3 work with an AGPLv3 work and conveying the result ("you have permission to link or combine any covered work with a work licensed under version 3 of the GNU Affero General Public License into a single combined work, and to convey the resulting work", https://www.gnu.org/licenses/gpl-3.0.txt). The engine parts stay GPLv3, the JUCE parts stay AGPLv3, and AGPLv3 section 13's network clause applies to the combination. OpenSession is a desktop application with no network interaction, and its own code is GPL-3.0-or-later, which is compatible with both inputs. No commercial JUCE or Tracktion licence is used; JUCE 8 and later have no splash-screen requirement under either route (JUCE team forum posts of 7 May 2024 and 12 June 2024; the splash mechanism is absent from the code). The commercial tiers exist (JUCE Indie USD 40/user/month or 800 once, Pro 175/month or 3,500 once; Tracktion Engine Indie USD 35/seat/month up to Pro 3 at 300/seat/month) but are not needed for an open-source distribution.

The draft research cites JUCE 8.0.8's licence text; the pinned submodule is JUCE 9.0.5, whose `LICENSE.md` carries the same dual-licence sentence and references the JUCE 9 EULA. The AGPLv3 option is unchanged.
